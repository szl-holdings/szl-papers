## 1 / NanoQuant (Samsung Research, ICML 2026)

- **Original screenshot:** first page of *NanoQuant: Efficient Sub-1-Bit Quantization of Large Language Models* by Hyochan Chong, Dongkyu Kim, Changdong Kim, Minseop Choi, PMLR Vol. 306 pp. 20335–20364. The table distinguishes PTQ and QAT; the screenshot calls NanoQuant the only sampled post-training method supporting 70B+, binary and sub-1-bit compression. This is a comparison of the paper's chosen baselines, **not** proof of exclusive capability in every other quantizer.
- **Paper:** https://proceedings.mlr.press/v306/chong26a.html (and arXiv:2602.06694); **author software:** https://github.com/SamsungLabs/NanoQuant at `a9e0a430881ff80d83b622c3129e330dc33c04f5`, Apache-2.0 per repo README.
- **Method:** weights are approximated with low-rank **binary bases plus scaling coefficients**. An ADMM initialization followed by non-factored/factored and block/model reconstruction uses calibration data; this is **post-training quantization**, not new gradient-trained foundational weights. The README lists OPT/Llama/Qwen/Gemma/Rnj support, CUDA binary GEMM (prefill)/GEMV (decode) kernels, example `--num_calib_samples 128`, and a CUDA compilation step.
- **Author-reported results:** 24× compression of Llama-2-70B in ~13 hours on a single H100 and 8GB-GPU serving; separate README plots report some decode kernel speedups. Neither indicates that SZL's A6000s will reproduce the throughput or that 70B inference remains accurate over arbitrary long context.
- **SZL route:** `szl-kernels` / `szl-serve` / `szl-engine-bench` / `szl-energy-attest`. **Not `szl-quant`**, an unrelated financial research strategy engine. First build a **non-training CPU source/oracle** and, separately on approved compute, compare BF16, AWQ/GPTQ and author binary kernels on an immutable eligible small model with held-out correctness, prefill/decode token throughput, TTFT, p95, peak VRAM, quantization hours, joules/token and rollback. A `safetensors` export cannot be assumed interoperable with existing inference runtimes.
- **HOLD:** model/license and calibration rights; code SHA and CUDA driver/SM pin; independent quality before/after; no GPU canary approved here.

## 3 / Deletion Tuning (NYU / Calgary, NeurIPS 2026)

- **Screenshot:** illustration shows training a gate logit for each selected MLP gate-projection weight, hard threshold `1[G>0]`, and making the deployed weight `W * 1[G>0]`. It shows an **8.4 MB** compressed mask for Llama-8B, paper-reported **83.55% versus FFT 83.24%** on GSM8K and **58.54% versus 58.43%** for Qwen3-30B-A3B SimpleRL-Zoo. These are **specific selected-validation results**, not a global "always matches full fine-tuning" guarantee.
- **Paper:** https://arxiv.org/abs/2611.10866 . **Author source:** https://github.com/agentic-learning-ai-lab/deleting-weights at `94f0340ebb574f95bb41d844165253a6785e215e`, MIT. The author release includes `src/learnable_sparsity`, GRPO via a **modified verl**, SFT, SDFT, mask application and evaluation.
- **Important code audit:** training modes have **different dependency environments** (GRPO Python 3.10, torch 2.8, vLLM 0.11, FlashAttention 2.8.3; SFT torch 2.7.1; SDFT Python 3.12). These do not map unchanged onto SZL's signed image pins. The released repository's **Roadmap has LoRA/MTH baselines and geometric analysis unchecked**: independent reproduction of the paper's full comparative plots requires other available source or your own verified baselines. Do not mark `reproduced` merely because the project has a license and weight masks.
- **Technical distinction:** a sparse *deletion mask* is a tiny **task adapter**. It does not necessarily make the underlying dense inference operation faster or free proportionate model memory. The base weights still exist and surviving weights may be processed densely. Evaluate **adapter disk savings and prior-task retention separately from inference speed**.
- **SZL route:** `szl-maskmod` is a reference kernel family, not already this optimizer; `szl-gpu-bridge`, `szl-abstention-frontier`, `szl-forge`. First adopt a synthetic, no-model-execution projection/mask contract and held-out mask-application oracle. Owner-approved GPU experiment only after exact base/target/optimizer/RNG, masks and independent backup are preserved. Compare LoRA, FFT, random mask, base and selected hidden-domain retention; verify refusal/abstention and false-confidence.

## 4 / CRAM energy reasoning (Prefrontal, 12 Nov 2026)

- **Screenshot:** *Classical Energies Learn to Reason 1,000× Faster than Looped Models*, Benjamin Hoover, Hugh Blayney, James C. R. Whittington, arXiv 2611.17309.
- **Source:** https://github.com/Prefrontal-AI/CRAM at `62bbe830c7d6f87f2ba18f30a28039258b986454`, Apache-2.0. Reproduction guide `REPRODUCING.md` and `uv.lock`, 91 tests claimed by authors.
- **Method:** learned Hopfield/Tank-style classical energy with a differentiable fit; search is energy descent with intrinsic stopping. The paper reports **99.996% Sudoku-Extreme**, **100% Maze-Unique**, fitting in **42 ms / 132 ms** on **one H200**, and at least 282× fewer FLOPs on the named Sudoku comparison. Those figures are **for this small learned energy model**, not arbitrary transformer fine-tuning or the total time to prepare/check all datasets.
- **Reproducibility exceptions:** the published guide says the Sudoku data-preparation command needs ~32 GB of memory / 2 GB output; the 412,786-puzzle Sudoku test, baseline fits and several exporters were **not rerun from the repackaged layout**. H200 Triton GPU kernels are not a plug-and-play CPU implementation. A small-source test is not a 1,000× SZL performance improvement.
- **SZL route:** `szl-cram`, `puzzle-frontier`, `lean-rlvr-proving-ground`, `lutar-lean`. Extend *only after* standalone SAT/SMT checker establishes puzzle solvability and uniqueness; include nonunique/impossible grids, paraphrase drift and untrusted-generated-problem negatives. Measure solved cases at fixed energy/inference FLOPs and real cost. No Lean theorem is established merely by an energy minimum.

## Engineering design rules extracted from the nine images

1. **One upstream immutable source per experiment**, with version, license, dependency lock, architecture/hardware boundary, dataset and benchmark revision. The four author-code source commits above were fetched through the authenticated GitHub connector; *that alone does not execute or validate upstream tests*.
2. **Falsification beats screenshots.** For every purported performance improvement, establish a matched baseline, denominator, negative controls, tested seed/window, hardware and confidence bounds *before* the run. Failed runs and refusals remain in the denominator.
3. **Do not mix efficiency metrics.** NanoQuant changes weight representation; Deletion Tuning changes task-adaptation bits; CRAM changes energy-search dynamics; AtlasKV changes knowledge access; harness evolution changes agent runtime controls. These require different quality, cost, memory, rights and rollback gates.
4. **No new operator/control plane.** Existing SZL trainer, guard, CI, source review, signed receipts, RLS and protected-Hub publication authorities are reused. Merge, deployment and promotion require separate independently observable gates.
5. **Mathematical ownership:** keep `lutar-lean` exact revision and `#print axioms` for formal claims, F1/F4/F7/F11/F12/F18/F19/F22 distinct from application modules; unconditional Λ uniqueness is **disproved as stated**, while conditional Theorem U is separate. Historical Khipu/Egyptian/Greek math exercises must be clearly labeled synthetic oracle tasks and not archaeological decipherment.
